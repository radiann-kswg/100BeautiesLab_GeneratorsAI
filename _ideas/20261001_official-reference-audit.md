## 原因と対応

| 情報 / 経路 | 従来の状態 | 修正 |
|---|---|---|
| AppearanceDetail[].img_PNGName | 93は両形態に attr_numberMarkNTS-93 を明示しているが、manifestの images に番号画像カテゴリがない | Formation が対象形態または null の宣言を使い、画像索引の実名・実パスへ照合 |
| attr画像の分類 | 索引140枚中、尾構造17枚以外の123枚は category: null。93の番号画像も other 扱い | カテゴリを勝手に変更せず、部位画像宣言に基づき採用 |
| 形態の絞り込み | 総当たりで93の番号画像を発見しても、コアフォルダの全体図用フィルタで消える | 部位図は形態宣言で選び、原点画像直後へ確保。未宣言・別形態のattrを混ぜない |
| Stage 2 | 設定画カテゴリ限定・先頭3枚のためattrを見ない | 部位図を役割付きで観察し、部位図分の枠を追加 |
| 番号プロンプト | DBの「Arabic numeral '93' (stylized motif)」に対し「not as stylized shapes, decorative glyphs」を要求 | 字形・線幅・間隔・切れ目・装飾を原典どおり保持し、別番号・汎用フォントへの置換を禁止 |
| 文字禁止指示 | 生成入口・修正・仕上げが「文字を一切描かない」を重ねて番号と競合 | 資料の注釈・署名等は禁止し、公式番号・紋章・衣装文字は再現する共通規則へ統一 |
| AppearanceDetailの残り | 番号のPosition/Color/Notation、モチーフのOverview等を個別抽出。その他の属性・左右・注記は直接渡らない | 対象形態の部位・左右・全Attrs・注記・画像名を原文で渡す。AIHintsは正典 |
| Stage 1要約 / i2i上書き | prompt_override で仕様文が欠ける可能性 | Gemini/OpenAIの送信境界で番号仕様・部位仕様を保持 |
| Stage 4 | 全体図の先頭1枚だけを比較し、番号の部位図は届かない | 全体図＋部位図をVisionへ直接添付。字形の違い・汎用フォントへの置換も修正対象 |
| Stage 5 | 単体はラフで参照枠を消費。合同はDB参照を外し完成レンダーだけを使用 | 部位図分の添付枠を確保。合同でも各キャラの部位仕様と部位図を添付 |
| ローカルとURL | 添付枠を増やすと同一の公式画像をURLから再取得・二重添付する可能性 | 既存URL resolverでローカルを再利用し、同じ実パスは一度だけ添付 |
| images.catalog | 新形式の直接収集キーに無く、総当たりへ依存 | 直接収集キーへ追加 |
| 合同分割CLI | 合成関数へ形態マップの代わりに文字列を渡す | 呼出元を形態マップへ修正し、各キャラの部位図も渡す |
